# Omniread 页面设计方向

日期：2026-11-19
状态：可实施规格
范围：`web/` 页面与样式；公开定价页依赖 gateway 放行 `GET /api/plans`（见 §B.4）

一句话定位：**不剧透的轻小说 RAG 阅读助手——「读到哪，聊到哪」**。中文长文沉浸阅读，旁边随时提问，回答带原文引用并可跳回章节；`past` 只依据已读章节，`full` 覆盖全书。

综合判断：

- **阅读面要消失**：正文区只保留纸面、文字、章节标题与极少的导航；工具栏在需要时出现。
- **引用要像批注，不像 SaaS 徽章**：引用角标是纸页上的朱批，点击回到原文；不做彩色胶囊堆叠。
- **定价页要像书店里的价目单，不像营销漏斗**：无渐变、无大数字倒计时、无“限时”压迫；四档并排、权益短句、直接 CTA。
- **公开页与登录后产品页是两套气质但同一套纸墨语言**：公开页可以有一张“阅读 + 问答”的静态示意图；登录后立刻进入安静的阅读界面。

## A. 艺术方向

### A.1 概念

**「纸页与朱批」**：暖纸底色、墨色正文、一个朱砂红作为唯一的品牌强调；引用、选中、当前章节使用朱批色；信息层级靠字号、字重、留白，而不是靠饱和色块。

关键词：纸感、墨色、窄版心、衬线、克制、中文标点讲究。不是通用 SaaS 仪表盘，不是花哨营销页。

### A.2 主色板（8 个核心 hex）

| 色值 | 名称 | 用途 |
| --- | --- | --- |
| `#F3EFE6` | 纸白 | 页面底色 `--bg`；公开页与书库的暖纸底 |
| `#FFFDF8` | 页面白 | 卡片、阅读面 `--surface`；比纯白暖一点 |
| `#25211B` | 墨色 | 主文字 `--text`；标题与正文 |
| `#A6452E` | 朱砂 | 品牌强调 `--accent`；主按钮、当前章节、引用角标 |
| `#3E5C76` | 黛青 | info / 引用链接 / 次要强调 `--info` |
| `#4A6B4F` | 苔绿 | success / 已保存 / 可用状态 `--success` |
| `#A9741F` | 赭石 | warning / 余额不足提示 / 高亮底色来源 `--warning` |
| `#8C2F2F` | 深朱 | danger / 删除 / 失败 `--danger`（与品牌朱砂拉开明度与冷暖） |

辅助中性色：`#6A6154`（次级文字）、`#968C7B`（弱化信息）、`#E3DBCB`（边框）、`#CFC4AF`（强边框）。暖中性用于纸面，冷中性仅用于管理页与深色模式。

### A.4 字体与中文排版

- **正文用衬线**：章节标题、正文、公开页大标题使用 `--font-serif`；按钮、表单、导航、表格使用 `--font-sans`。
- **不引入 Web 字体作为首版硬依赖**。中文字体体积大，首屏代价高；先走系统栈。Windows 上若缺 `Noto Serif SC`，`SimSun` 在小字号偏细，因此把正文默认字号定在 **19px**，最小 16px，避免 12–14px 的宋体正文。
- **默认字号要同步两处**：`web/src/style.css` 的 `--reader-font-size: 19px` 与 `web/src/stores/settings.ts` 的 `readFontSize()` 无存储时返回值都改为 19；否则 store 的 `apply()` 会在挂载时覆盖成 18px。
- 若后续要统一纸感，再自托管一个子集字体（首选「霞鹜文楷 Lite」或 Source Han Serif SC 常用字子集，WOFF2，控制在 6–8MB 内）；不要同时加载两套中文字体。
- 正文参数：
  - 字号 `--reader-font-size: 19px`，设置页可调 16–26px；行高 `1.95`；字距 `0.012em`。
  - 版心 `--reading-measure: 36rem`（浏览器默认 16px root 下约 576px，19px 正文约 30 个汉字/行）；不要拉满 760px 容器。
  - 首行缩进 `2em`；段间距 `0.9em`；`text-align: justify;`；`overflow-wrap: break-word;`。
  - 章节标题 `clamp(24px, 3vw, 32px) / 1.5`，字重 600，字距 `0.02em`；章前小字 `11px / letter-spacing: 0.2em`。
- 标题层级：
  - 公开页 hero：`clamp(40px, 6vw, 64px) / 1.18`，serif，600。
  - 页面 h1：`clamp(28px, 4vw, 40px) / 1.3`，serif，600。
  - 区块 h2：`20px / 1.4`，serif 或 sans 600。
  - 卡片标题：`16px / 1.5`，sans 600。
  - 正文 UI：`14px / 1.6`；meta：`12.5px`；micro：`11px`。
- 数字统一 `font-variant-numeric: tabular-nums`，用于积分、余额、价格、进度、日期。
- 标点：中文引号、省略号、破折号按中文排版；不在标题里混用英文半角括号。
- 代码/模型 ID/Key 掩码用 `--font-mono`。

### A.5 间距、圆角、阴影、边框、动效

- 间距只用 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96。
- 页面容器：宽版 `min(1120px, 100%)`；正文/定价正文 `min(1000px, 100%)`；阅读版心 `36rem`。
- 圆角：4（角标）/ 6（输入、按钮）/ 8（面板）/ 12（书封、公开页卡片）；**不再使用 18px 大圆角**，避免 SaaS 感。
- 边框：1px 实线；focus 用 2px `--accent` + 2px offset，不叠加阴影。
- 阴影：只用于书封、对话卡、浮层；阅读正文、面板默认无阴影，用边框和底色分层。
- 动效：
  - 时长 140–240ms，`--ease-out`；只做透明度、位移 1–4px、背景色变化。
  - 悬停：书封 `translateY(-3px)`，按钮背景变深一档；不做缩放。
  - 入场：页面区块 `opacity 0 → 1` + `translateY(4px)`，200ms；不做逐条瀑布。
  - 引用命中：高亮底色 600ms 内从 `--quote-bg` 到透明再回一半，滚动 `behavior: smooth`。
  - 遵守 `prefers-reduced-motion: reduce`（现有全局规则保留）。
- 滚动条：8px 宽，thumb `--border-strong`，圆角 999，3px 透明边框，track 透明；阅读区滚动条更细（6px），不常显。

### A.6 不要什么

- 不要紫色/蓝色渐变 SaaS 风、渐变文字、发光按钮。
- 不要玻璃拟态堆叠；顶栏最多用 92% 不透明底色，不用大面积 backdrop blur。
- 不要营销大字报、倒计时、红色“限时”角标、夸张数字。
- 不要满屏 card + 彩色图标；图标用 1.5px 线宽的内联 SVG，不用 emoji。
- 不要高饱和封面墙、活动 banner、自动轮播。
- 不要给正文加阴影、纹理贴图或纸张噪点图片；纸感来自颜色、留白、字体与边框。

## B. 信息架构与路由

### B.1 当前问题

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 书库占用了 `/` | `router/index.ts` 中 `/` 指向 `LibraryView` 且 `requiresAuth` | 访客打开首页直接被踢到登录页，没有产品介绍 |
| 套餐页需登录 | `/plan` 设 `requiresAuth` | 未登录无法查看定价 |
| 登录后默认回 `/` | `LoginView` 的 `redirectTarget` 默认 `/` | 登录后落到书库（未来会落到公开落地页），语义错误 |
| 守卫特判 `/` | `to.fullPath === '/' ? {}` 不写 redirect | `/` 改为公开后该特判失效，且会丢目标地址 |
| 导航指向 `/` | `UserTopbar`、`ReaderView`、`AdminView` 多处 `to="/"` | 改成公开落地页后会变成“返回首页”，与“返回书库”语义不符 |
| 套餐链接指向 `/plan` | `UserTopbar`、`ReaderView`、`ChatPanel`、`SettingsView` | 路由改名后全部死链 |
| 公开定价页会 401 | `PlanView` 挂载即 `fetchAccount()`；gateway 的 `AuthInterceptor` 拦截全部 `/api/**`，仅放行 `/api/auth/login` | 访客进入 `/plans` 会报账户错误 |

### B.3 守卫逻辑

```ts
router.beforeEach(async (to) => {
  const hasToken = Boolean(localStorage.getItem(TOKEN_KEY))

  // 已登录访问登录页：回到 redirect 或书库
  if (to.name === 'login' && hasToken) {
    const target = safeInternalRedirect(to.query.redirect)
    return target ?? { name: 'library' }
  }

  // 受保护页未登录：带完整目标地址去登录
  if (to.meta.requiresAuth && !hasToken) {
    return { name: 'login', query: { redirect: to.fullPath } }
  }

  // 管理员校验：只在这一步请求账户
  if (to.meta.requiresAdmin) {
    const account = await useAccountStore().fetchAccount(true)
    if (!account) {
      return { name: 'login', query: { redirect: to.fullPath } }
    }
    if (account.role !== 'admin') return { name: 'library' }
  }

  return true
})

function safeInternalRedirect(value: unknown): string | null {
  return typeof value === 'string' && value.startsWith('/') && !value.startsWith('//')
    ? value
    : null
}
```

规则：

- 公开页不拦；不调用账户、Key、会话接口。
- 登录页已登录直接跳 `/library`；`redirect` 只接受站内绝对路径，拒绝 `//evil`。
- 受保护页未登录跳 `/login?redirect=<fullPath>`；登录成功后优先回 `redirect`，否则 `/library`。
- `/admin` 先校验 token，再强制 `fetchAccount(true)` 校验 `role`；非管理员回 `/library`，不显示管理入口。
- 不再使用 `to.fullPath === '/' ? {}` 这类特判。

### B.4 后端前置条件（公开定价页）

当前 `gateway/src/main/java/com/omniread/config/WebConfig.java` 把 `/api/**` 全部拦截，仅排除 `/api/auth/login`；`AccountController` 的 `GET /api/plans` 因此对访客返回 401。

二选一，推荐同时做：

1. gateway 在 `excludePathPatterns` 增加 `"/api/plans"`，让套餐目录公开只读；`POST /api/me/plan` 仍受保护。
2. web 侧保留静态兜底 `FALLBACK_PLANS`（0/20/60/100，100/500/2000/4000），仅在无 token 且目录请求失败时使用，避免公开定价页白屏。

公开页硬性约束：**有 token 才调用 `/api/me/account`、`/api/me/api-keys`**；无 token 时不要发这些请求，也不要因为 401 在页面上显示错误。

## D. BYOK 模型列表修复

### D.1 根因

- `web/src/stores/reader.ts` 的 `loadProviderModels` 在 `catch` 中执行 `providerModels.value = []`，一次失败就把列表清空。
- `setProvider` 切换 provider 时执行 `setByokModel('')`，并清空 `providerModels`，所以切换后下拉必空。
- `ChatPanel` 仅在 `activeKey` 存在时渲染模型下拉；无 Key 时直接显示 `配置 Key`，用户看不到任何建议模型。
- 首次进入自己模式、尚未点“拉取”时，`providerModels` 为空，下拉没有内容。

### D.2 数据结构

新建 `web/src/utils/models.ts`（或放在 `utils/billing.ts` 同级）：

### D.3 reader store 合并逻辑

```ts
const pulledModels = ref<Partial<Record<ApiProvider, string[]>>>({})
const providerModelsError = ref('')
const providerModelsLoading = ref(false)

const suggestedModels = computed(() => SUGGESTED_MODELS[provider.value] ?? [])
const availableModels = computed(() => {
  const pulled = pulledModels.value[provider.value]
  return pulled && pulled.length > 0 ? pulled : suggestedModels.value
})
```

规则：

1. **建议列表为底**：没有拉取结果、没有 Key、拉取失败、拉取为空时，`availableModels` 始终返回 `SUGGESTED_MODELS[provider]`，下拉不为空。
2. **拉取结果覆盖**：拉取成功且非空时，用返回的列表替换该 provider 的显示列表；排序按后端（已字母序）或前端 `localeCompare`。
3. **切换 provider**：
   - 不清空 `providerModelsError` 之外的已拉取缓存（按 provider 分开存）；
   - 若当前 `byokModel` 不在新 `availableModels` 中，选 `availableModels[0]`；
   - 不再执行 `setByokModel('')`。
4. **拉取失败**：
   - 保留该 provider 上一次的拉取结果（如果有），否则显示建议列表；
   - 设置 `providerModelsError = '拉取失败，仍显示建议模型'`；
   - 不清空 `pulledModels`。
5. **拉取成功但空列表**：
   - 不覆盖建议列表（或视为无拉取结果）；
   - 提示 `该 Key 未返回模型，已保留建议列表`。
6. **无 Key**：
   - 仍显示建议列表与当前选择；
   - `askProblem` 返回 `请先在设置中保存该提供商的 API Key。`；
   - 发送禁用，显示 `配置 Key` 链接；
   - `拉取` 按钮禁用。
7. **持久化**：保留 `omniread.byokProvider`、`omniread.byokModel`；切换 provider 后写入该 provider 的首个可用模型，刷新页面仍可用。不要新增后端字段。

## G. 验收口径

1. **公开可看**：未登录能完整浏览 `/` 与 `/plans`；无 401、无空白、无登录弹窗。
2. **导航不混**：公开页只有“产品/定价/登录”；登录后只有“书库/套餐/设置/管理/退出”。
3. **阅读优先**：阅读页首屏是正文，不是仪表盘；正文版心 36rem、19px/1.95、2em 缩进。
4. **引用可回**：每条引用有章节标签，点击跳章并高亮；找不到时明确提示。
5. **防剧透语义可见**：`已读/全书` 切换在对话头部；`全文` 不改变现有 RAG 过滤逻辑。
6. **BYOK 不空白**：四个 provider 在无 Key、未拉取、拉取失败时都有建议模型；发送前必校验 Key。
7. **计费不误导**：定价页写清“平台 1 积分/次、BYOK 不扣、失败不扣、续费重置、余额只买套餐”。
8. **构建通过**：`cd web && npm run build` 成功，无 TypeScript 错误。
