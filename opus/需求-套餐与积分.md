# 套餐、积分与 BYOK 需求

日期：2026-11-20
状态：已定

## 1. 套餐与订阅

| 档位 | 价格（元/周期） | 每周期积分 |
| --- | --- | --- |
| free | 0 | 100 |
| plus | 20 | 500 |
| pro | 60 | 2000 |
| ultra | 100 | 4000 |

- 付费套餐从购买日起计算 1 个月，到期需续费。
- 周期内积分用完不补；续费开启新周期，积分重置为该档额度，未用完不结转。
- free 按 1 个月周期补充 100 积分，到期自动续 free。
- 付费套餐到期未续费时回落 free：重置为 100 积分、开新周期。
- 管理员建号：默认 `free` 档、100 积分、20 余额。
- 自助注册（2026-11-20 起）：默认 `free` 档、100 积分、**0 余额**；展示名缺省用用户名；
  `role` / `plan` / `credits` / `balance` 字段一律服务端定值，不接受请求传入。

## 2. 两种回答模式

1. **BYOK**：用户按提供商填入自己的 API Key，并选择该提供商下的模型；回答不消耗积分。
2. **平台模式**：使用平台 Key 或免费渠道，每次回答固定消耗 **1 积分**；回答失败不扣。

- `free` 档平台模式只有 `auto`：自动路由可用免费渠道，不能选模型。
- `plus` / `pro` / `ultra` 平台模式可选择模型。
- BYOK 对所有档位开放；用户只提供对应提供商的 Key，模型由用户选择。

## 3. 免费渠道与 auto

- 平台维护免费渠道池：提供商、模型、加密 Key、状态、优先级、最近使用时间。
- `auto` 按优先级和可用性选择渠道，失败切下一个；对用户只暴露「auto」。
- 渠道 Key 只在 rag 进程内使用，不下发前端、不写日志。

## 4. 余额与购买

- 不接支付网关；套餐用站内余额购买。
- 余额来源：管理员发放；不开放真实支付。
- 套餐购买：余额 ≥ 价格时扣余额、设置档位与 1 个月周期、积分重置为该档额度。
- 不做余额兑积分；余额只用于购买套餐。

## 5. 数据模型

| 表 | 关键字段 |
| --- | --- |
| `user` | `role(admin/user)`、`plan`、`credits`、`plan_started_at`、`plan_expires_at`、`balance` |
| `plan_catalog` | `code`、`price`、`credits`、`duration_days` |
| `balance_ledger` | `user_id`、`type`、`amount`、`balance_after`、`ref`、`created_at` |
| `credit_ledger` | `user_id`、`type`、`amount`、`balance_after`、`ref`、`created_at` |
| `user_api_key` | `user_id`、`provider`、`encrypted_key`、`key_mask`、`status`、`created_at`、`last_checked_at` |
| `model_catalog` | `provider`、`model`、`display_name`、`plans`、`byok_supported`、`status` |
| `usage_record` | `user_id`、`session_id`、`mode`、`provider`、`model`、`prompt_tokens`、`completion_tokens`、`credits` |
| `purchase_record` | `user_id`、`plan`、`amount`、`balance_after`、`created_at` |

免费渠道不落 gateway 库：由 rag 侧 `channels.json`（gitignore）维护 provider/model/key/priority，gateway 不持有渠道 Key。

## 6. API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/plans` | 套餐与价格 |
| POST | `/api/auth/register` | 自助注册（free/100 积分/0 余额），返回登录态 |
| GET | `/api/me/account` | `{role, plan, credits, balance, planExpiresAt}` |
| POST | `/api/me/plan` | `{plan}`，余额购买并开启新周期 |
| GET/POST/DELETE | `/api/me/api-keys` | BYOK Key，只返回掩码 |
| GET | `/api/models?mode=platform\|byok&provider=` | 可选模型 |
| POST | `/api/chat/sessions/{id}/ask` | 增加 `mode`、`provider?`、`model?` |
| POST/GET | `/api/admin/users` | 管理员建号 / 列表 |
| POST | `/api/admin/users/{id}/balance` | 管理员发放余额 |

`ask` 校验：

- `free`：只允许 `mode=auto`；
- 平台模式：积分 ≥ 1，成功后条件扣减并写 `credit_ledger` / `usage_record`；
- BYOK：该提供商已存 Key，模型 `byok_supported=true`，不扣积分；
- 任意模式失败不扣积分。

## 7. RAG 契约

- `AskRequest` 增加 `mode`、`provider`、`model`、`api_key`（仅 BYOK，请求内传递，不落库、不写日志）。
- `auto` 由 rag 的免费渠道池路由；返回实际 `provider`、`model`、token 用量。
- 平台与免费渠道 Key 只在 rag 进程内使用；gateway 不持有免费渠道 Key。
- 所有模式统一输出 `citations`、`usage`。

## 8. 安全

- 用户 Key 用 AES-GCM 加密存储，主密钥只放 `gateway/application-local.yml`。
- 接口只返回掩码（如 `sk-…abcd`）；任何日志、异常信息不得带明文 Key。
- 管理员接口按 `role=admin` 校验；JWT 增加 role 声明。

## 9. 当前实现口径

- free 每 1 个月补充 100 积分；付费到期回落 free。
- 平台回答固定 1 积分/次；BYOK 不扣积分；失败不扣。
- 管理员建号：free、100 积分、20 余额；自助注册：free、100 积分、0 余额。
- 管理员体系独立：`/api/admin/auth/login` 单独颁发 admin token，前端 `omniread.admin.token`
  与用户 `omniread.token` 分离互不冒用；admin 接口按 `role=admin` 校验。
- 余额只买套餐，不做兑积分。
- BYOK 首批提供商：百炼、OpenAI、DeepSeek、硅基流动（均为 OpenAI 兼容端点）。
- 管理员操作先走 API；web 管理页作为后续任务。
- 免费渠道放在 rag 的 `channels.json`，由管理员手动维护。
