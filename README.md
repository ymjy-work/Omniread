# Omniread

一个能「边读边问」的小说问答系统。

阅读页放着小说原文，旁边可以随时提问；回答由 AI 生成，**逐处标注它依据的章节**，
点角标就跳到那一章。检索范围跟着你的阅读进度走——读到第 N 章，就只让它看第 N 章之前的内容，
不会把后面的剧情漏出来。

## 演示内容

《不时轻声地以俄语遮羞的邻座艾莉同学》（日语轻小说，15 卷 / 193 章）。

- **阅读页**开放第 1 卷共 11 章（含插图）
- **问答**覆盖全书——这是刻意的取舍：阅读范围收窄是为了控制原文的展示量，
  问答要能展示检索与评测的能力，所以不跟着收窄
- 章节列表列出全部标题，第 1 卷之外的标记为锁定

## 能做什么

- **按进度提问**：`past` 档位把检索范围限制在阅读进度之内；`full` 档位放开全书
- **答不了就说答不了**：材料不足时明确拒答，不猜、不编
- **出处可核**：回答逐句带引用，角标可跳回原文
- **流式回答**：边生成边显示，等待期给出阶段与已等待时长
- **读出处的书**：章节正文按受限 Markdown 渲染，插图随章节展示

## 怎么做的

一句话：**语料 → 切片与向量化 → 双路检索融合 → 重排 → 装配 → 模型作答 → 引用回链**。

检索与回答被做成**可复现的单轮基线**——有冻结的评测题集、逐题产物与公开的基线数字，
而不是只有一次演示。评测只做**确定性**判断（引用是否越界、该拒答的有没有拒答），
不引入模型裁判。

## 组成

| 部分 | 是什么 |
| --- | --- |
| Java 网关 | 对外唯一入口：阅读范围、阅读进度、静态资源托管 |
| Python RAG 服务 | 检索链、上下文装配、回答链、评测管线 |
| Web 前端 | Vue 3 + Vite + TypeScript；书库 → 章节 → 正文 → 提问 → 流式回答 |
| 基础设施 | PostgreSQL + pgvector（向量检索）、MinIO（插图与语料归档） |
